## Cómo leer los diagramas

- Color de la flecha y etiqueta = estado de implementación: implemented = implementado; partially implemented = implementado en parte (`[partial]`); implemented differently = implementado de otra forma (`[differs]`); modeled, not implemented = modelado, no implementado (`[not implemented]`); external, not verifiable in code = externo, no verificable en el código (`[external]`).
- Texto en cursiva: implementación no modelada (sin relación en `architecture.yml`). Las cajas blancas
  con borde discontinuo («implementation-only») son participantes que solo existen en el código.
- Flecha continua: llamada síncrona. Discontinua con punta abierta: mensaje asíncrono (broker, cola,
  outbox). Discontinua con punta llena: respuesta. Flecha sobre el mismo participante: paso interno.
- Una relación del contenedor se acepta para un participante componente y al revés; las respuestas
  recorren la relación en sentido inverso.
- Las notas aparecen en la vista completa (`out/<id>.svg`). Las figuras para documentos están en
  `out/figuras/05-secuencias/`.

## seq_a1_capture: CI/CD failure capture: from the GitHub Actions webhook to the Recommendation receipt

Figura completa: [seq_a1_capture.svg](seq_a1_capture.svg). Fuente: `build/seq_a1_capture.puml`.

Primera mitad del flujo de fallo: un run fallido de GitHub Actions llega por webhook firmado, se admite contra el ámbito de captura, queda en un recibo durable, se prepara con el token de instalación, se normaliza y protege, se congela en el outbox y se publica en Service Bus; las tres suscripciones lo consumen y Correlation entrega el contexto a Recommendation, que solo registra un recibo y un job de diagnóstico.

### Sin prueba de integración

Según la auditoría de solo lectura del 27/11/2026; no se ha ejecutado ningún flujo para esta guía.

- Ningún salto entre servicios se prueba con el par real: todos usan stubs, fakes o HttpServer locales.
- Ninguna prueba usa un Service Bus real ni el emulador: filtros, deduplicación, maxDeliveryCount, DLQ y TTL solo se comprueban en el plan de Terraform.
- Las pruebas HTTP del webhook simulan CaptureHandler; ninguna recorre servlet → JdbcCaptureAuthority → ledger.
- La lectura de GitHub (token de instalación, run, jobs y logs) solo se prueba contra un HttpServer local, nunca contra GitHub.
- La comprobación de ámbito de máquina con JdbcCaptureAuthority, la que corre en runtime, no tiene prueba directa.
- No hay prueba extremo a extremo automatizada en los repositorios de servicio.

## seq_a2_diagnosis: Assisted diagnosis: job, RAG retrieval, Azure OpenAI inference and summary projection

Figura completa: [seq_a2_diagnosis.svg](seq_a2_diagnosis.svg). Fuente: `build/seq_a2_diagnosis.puml`.

### Fragmentos

- `opt` replay:
  - [diagnosis already admitted with the same fingerprint] → paso 8
- `alt` retrieval result:
  - [matches] → paso 13
  - [no_match] → paso 14
  - [429, 5xx or transport failure] → paso 15
  - [401, 403 or 422] → paso 16
- `alt` inference outcome:
  - [timeout, non-2xx (including the content filter), finish_reason not stop or refusal] → paso 20
  - [invalid shape or citation, or prompt over 128 KiB] → paso 21
  - [valid hypothesis] → paso 22
- `alt` settlement of the job:
  - [valid hypothesis] → pasos 23–24
  - [invalid_context or admission_conflict] → paso 25
  - [retryable failure] → pasos 26–27
  - [lease expired while the first worker is still running] → paso 28
  - `loop` backoff 30 s x 2^(n-1), 30 min cap, up to 8 attempts (about 61 min):
    - [attempts below 8] → paso 26
- `alt` projection result:
  - [200 with a valid echo] → pasos 32–33
  - [400 or 409, for example SCOPE_MISMATCH for an execution that is not ORIGIN] → paso 34
  - [404, 401, 403, 5xx, timeout or invalid echo] → paso 35
  - `loop` indefinitely, backoff 2 s x 2^(n-1) with a 10 min cap:
    - [not accepted] → paso 35

### Sin prueba de integración

Según la auditoría de solo lectura del 27/11/2026; no se ha ejecutado ningún flujo para esta guía.

- Ningún test cruza servicios: en RecommendationApiTest la inferencia es un bean sustituto y RAG responde siempre no_match, así que el camino con fragmentos y fuentes no se recorre integrado.
- Pipeline es un HttpServer falso para entitlements y resúmenes; la coherencia del contrato depende de fixtures espejo.
- Sin prueba: timeout real del LLM, content_filter, prompt mayor de 128 KiB, reintentos del job por fallos del LLM, RAG 401 y 422 explícitos, invalid_context, admission_conflict y el bucle indefinido del outbox con 404 o 401.
- Embeddings solo con cliente falso; pgvector solo con embeddings deterministas. Nunca contra Azure OpenAI real.
